# 交给 AI 搭建跃映

将下面的提示词连同本仓库链接交给你使用的 AI 编程工具。先填写本机环境、目标设备和允许执行的范围；账号、密码、私钥、Cookie、完整登录二维码不应放进提示词、日志或公开 Issue。

## 先提供这些信息

| 信息 | 示例或填写方式 |
| --- | --- |
| 开发电脑 | macOS / Windows / Linux，CPU 架构，SDK/JDK 是否已安装 |
| 目标端 | Android 手机 + Android TV；或 HarmonyOS 手机 + Android TV |
| 安装方式 | 真机、模拟器或已有 AppTest 邀请；不要假设已有市场包 |
| 电视 | 系统版本、可否安装 APK；IP/端口只在私有协作中提供 |
| 用户可操作的授权 | 是否能在设备确认 ADB、DevEco 签名和第三方 SDK 协议 |
| 已有资料 | 仓库路径、已有签名位置、已有构建；不提供签名内容或密码 |

## 可直接使用的提示词

```text
请帮我从 https://github.com/Dcelysia/yueying 搭建跃映。
先阅读根 README、docs/setup.md、相关端 README、sources.lock.json 和适用 AGENTS.md。

我的环境与目标：
- 开发电脑与架构：[填写]
- 已有源码路径或允许新建的位置：[填写]
- 目标端与系统：[填写]
- 真机/模拟器：[填写]
- 允许执行的安装、构建和设备操作：[填写]

工作要求：
1. 先检查已有环境与仓库状态，再沿脚本和锁定版本搭建。保留我已有源码、分支、SDK、签名和设备数据；缺失资料才向我询问。
2. Android 手机/电视与 HarmonyOS 使用配套但独立的工具链。不要用 Flutter-OH 覆盖 Android Flutter，也不要任意升级依赖。 Apple Silicon 构建锁定版本的鸿蒙 release 若报 Bad CPU type in executable，先检查其 x86_64 gen_snapshot 所需的 Rosetta；安装前由我确认 Apple 许可，使用普通交互安装，不默认添加 --agree-to-license，也不替换其他引擎的 gen_snapshot。
3. HarmonyOS 第一版只浏览和遥控，不加入手机本地视频播放；Android 原有本地播放保留。
4. 电视独立取流；手机只发送视频身份和控制命令。保留 A/B 多手机同步，B 进入现有控制页不得重播或重置进度。
5. 先完成最小可构建结果，再按我授权范围安装。ADB、DevEco 设备信任、账号登录、SDK 协议由我确认；不要自动代签新协议或绕过系统授权。
6. 使用我实际提供的 IP/端口，不套用维护者家中的地址；不把 ADB 或 9838 映射到公网，不改路由器、不替换电视系统桌面，不刷机、不 root。
7. 不打印或提交签名、密码、令牌、Cookie、设备私有数据。不为了构建卸载旧应用、清除账号、删除资料或重置设备；需要会丢数据的动作先说明并让我决定。
8. 保留 PiliPlus GPL-3.0、NeoBV MIT 及第三方 LICENSE/AUTHORS/版权头，明确这是二次开发；我自己的改动不能抹掉原作者权益。分发时提供包含实际改动的对应源码。
9. fork 发布时使用我真实确认的公开运营者资料及源码/政策地址，不沿用他人身份；构建成功不等于商店审核通过，不替我提交外部审核或接受新条款，除非我另行明确授权。
10. 记录实际命令、失败原因与产物位置。验证至少包括：连接电视、A播放、B进入不重播、A切视频B同步、进度/音量/选集、手机返回电视不停播。没运行或没通过的检查如实写清。

先给出当前环境缺项和最短实施步骤，然后在上述授权范围内执行。
```

## 最终应拿到什么

- 本次源码版本或 commit、遵守原许可的完整修改、可重复的构建步骤。
- Android 的两个配套 APK，或鸿蒙有效签名的开发 HAP / 实际提交所需 release APP。
- 准确的设备安装结果和 A/B 同步验证记录，标出真机、模拟器及端口转发的区别。
- 未完成项目及原因，例如缺个人发布签名、未公开政策地址、尚未创建邀请码；不要把未发生的审核或安装写成完成。
